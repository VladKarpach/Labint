# Техническая документация: лидерборд игрового рейтинга

## Архитектура

```
Игровой сервер ──POST /scores──┐
Клиенты (веб/моб.) ──GET ...───┼──> HTTP API (src/server.py) ──> State (в памяти)
Администратор ─POST /season/reset┘
```

Это учебный MVP. Весь код API лежит в одном файле `src/server.py` (стандартная библиотека Python, без зависимостей). Данные хранятся **в памяти процесса** и пропадают при перезапуске. В реальном сервисе состояние нужно вынести в БД или Redis (сортированное множество удобно для топ-K), а контракт API при этом не меняется: он описан в `openapi.yaml`.

## Структура репозитория

| Путь | Назначение |
|------|-----------|
| `README.md` | Постановка, обзор, навигация |
| `docs/user.md` | Руководство пользователя |
| `docs/tech.md` | Этот документ |
| `openapi.yaml` | Спецификация OpenAPI 3.0.3 |
| `src/server.py` | Stub-реализация API и раздача Swagger UI |

## Запуск

```bash
python src/server.py
```

Сервер слушает порт 8000. Swagger UI: `http://localhost:8000/docs`, спецификация: `http://localhost:8000/openapi.yaml`, проверка работоспособности: `GET /health`. Страница Swagger UI подгружает скрипты с CDN, поэтому нужен доступ в интернет.

## Конфигурация (переменные окружения)

| Переменная | По умолчанию | Назначение |
|-----------|--------------|-----------|
| `LEADERBOARD_API_KEY` | `dev-api-key` | Ключ игрового сервера (заголовок `X-API-Key`) для `POST /scores` |
| `LEADERBOARD_ADMIN_TOKEN` | `dev-admin-token` | Токен администратора (заголовок `X-Admin-Token`) для `POST /season/reset` |
| `PORT` | `8000` | Порт сервера |

Значения по умолчанию годятся только для локальной разработки. В любом общедоступном окружении их нужно задавать через переменные окружения (секреты CI/хостинга), а не хранить в коде.

## Модель игрока

| Поле | Тип | Ограничения |
|------|-----|-------------|
| `nickname` | string | 3–20 символов `[A-Za-z0-9_-]`, уникален без учёта регистра; хранится в написании первого начисления |
| `score` | integer | ≥ 0, сумма очков в текущем сезоне |
| `rank` | integer | ≥ 1, вычисляется при чтении, не хранится |
| `updated_at` | date-time (UTC) | момент последнего начисления, т. е. когда игрок набрал текущее количество очков |

Внутри хранилища игрок — запись `{nickname, score, reached_at}` по ключу `nickname.lower()`.

## Правила ранжирования

Сортировка по ключу `(-score, reached_at, nickname.lower())`: больше очков — выше; при равенстве выше тот, кто набрал очки раньше; при совпадении времени — по алфавиту. Так порядок всегда однозначный, и места не повторяются.

## Начисление очков

`POST /scores` прибавляет `points` (1–10 000) к очкам игрока и создаёт игрока при первом начислении. Ограничение размера одной операции снижает ущерб от ошибки или компрометации ключа. Уменьшение очков и установка произвольного значения не поддерживаются.

## Сезон и сброс

В хранилище есть номер сезона и время его начала. `POST /season/reset` выполняет по порядку:

1. Проверяет токен администратора (иначе `401`).
2. Проверяет, что в теле передано `confirm: true` (иначе `400`): защита от случайного вызова.
3. Копирует результаты текущей таблицы в архив.
4. Увеличивает номер сезона и очищает таблицу.

Архив в stub тоже хранится в памяти и отдельным эндпоинтом пока не публикуется (это возможное расширение API). Операция необратима для текущей таблицы, поэтому в реальной системе её стоит запускать по расписанию или с журналированием вызова.

## Ошибки

Все ошибки возвращаются как `{"error": "<описание>"}` с кодами `400` (некорректный запрос), `401` (нет или неверен ключ/токен), `404` (игрок не найден). Единая схема `Error` описана в `openapi.yaml`.

## Проверка спецификации

Структуру `openapi.yaml` можно проверить в [Swagger Editor](https://editor.swagger.io) (вставить содержимое файла) или командой `npx @redocly/cli lint openapi.yaml`. Поведение stub-сервера покрывает все 6 операций спецификации.
